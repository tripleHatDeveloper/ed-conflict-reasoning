# Conflict reasoning for a cognitive digital twin of emergency department patient flow

This repository contains the code behind the experiments of the accompanying article. It has a simulated emergency department (31 bays in five zones), a framework that interprets and resolves conflicts between data sources, three conventional fusion methods used as baselines, and a comparison of global and local conflict resolution for departments of up to 744 bays. All patient data are synthetic and are generated by the simulator from a seed.

## Requirements

Python 3.10 or later and the packages in `requirements.txt`:

    pip install -r requirements.txt

Conflict resolution uses the CP-SAT solver of OR-Tools. The results were produced with version 9.15.6755, which is pinned because the solutions can differ between versions. Every solve runs on a single thread.

## Running the experiments

New runs are written to `outputs/`.

| Command | What it runs | Time on one core |
| --- | --- | --- |
| `python run.py experiment1` | The framework and the baselines on 20 simulated weeks under the normal faults, and on the stress test (three times the faults and a surge day) | about 5 hours |
| `python run.py sensitivity` | The same evaluation with 11 assumptions of the simulator varied one at a time and together | about 8 hours |
| `python run.py scalability` | Global resolution (limited to 30 minutes) against local resolution with margins of 3, 6 and 9 slots, for 31 to 744 bays | about 10 hours |

Add `--quick` to any of them for a test run of a few minutes. `experiment1` and `sensitivity` also accept `--workers N` to run independent weeks in parallel, in which case the decision times reflect the load of the machine. The stress test is a single run (seed 31); the number of weeks under the normal faults is set with `--weeks`. A stopped run continues where it stopped when the same command is repeated.

## Checking the results

The folder `results/` holds the run files behind the reported tables. To print the tables from them:

    python run.py summary

With `--dir outputs` the same command prints the tables of a new run. To re-run the first simulated week and a 31 bay comparison and compare them with the stored files (about 15 minutes):

    python run.py verify

Apart from run times, which depend on the machine, the results are reproducible for a given seed.

## Synthetic data

`python run.py data --seed 11` writes the observations of the data sources with their fault labels and the state of every bay for one simulated week. The folder `data/` contains the files for seed 11. The parameters of the simulator and the framework are listed in `parameters.md`.

## Layout

    run.py                 command line entry point
    parameters.md          parameters of the simulator and the framework
    requirements.txt
    src/
      layout.py            zones and bays
      sim.py               simulator and error models of the data sources
      model.py             constraint model and encoding of the observations
      resolve.py           calibration, local and global resolution, dispute analysis
      analysis.py          evidence and dispute measures, prediction
      evaluation.py        fusion strategies, one evaluated week, metrics
      study.py             experiment 1 and sensitivity analysis
      report.py            tables of the study
      scalability.py       global against local resolution, 31 to 186 bays
      scalability_large.py the same for 372 and 744 bays
      summary.py           tables from run files
      generate_data.py     synthetic data of one week
      verify.py            comparison with the stored results
    results/               run files behind the reported tables
    data/                  synthetic data of one week
